# CacheGate

**Codex CLI 的会话空闲提醒插件。** 同一会话上一轮执行结束或中断后，空闲超过 30 分钟再发送消息时，默认提醒后继续发送，也可切换为拦截，由你决定是否继续。

长时间空闲后，提示词缓存（KV 缓存）可能失效，重新处理长上下文可能增加耗时和输入费用。CacheGate 帮助你在发送前留意这笔开销，决定继续当前会话或手动 `/clear` 新建会话。

提交、执行结束或中断时，各运行一次短暂的本地 Python hook：无需第三方 Python 依赖，不开启常驻进程，不调用模型，提示不进入模型上下文。

## 快速开始

需要 **Python 3.10+** 和支持 `UserPromptSubmit`、`Stop`、`Interrupt` command hook 的 Codex CLI。已验证环境：Linux、Python 3.12.3、Codex CLI/app-server 0.155.0。

**1. 在终端安装**

```bash
codex plugin marketplace add Chlience/codex-cachegate --ref main
codex plugin add cachegate@cachegate
```

**2. 在 Codex 中信任 hook**

新建 Codex 会话，打开 `/hooks`，审阅并信任 CacheGate。安装后默认仅提醒，无需先配置。

**3. 在 Codex 输入框查看帮助**

单独提交以下内容，无需 `!` 或其他前缀：

```text
cachegate help
```

之后正常使用即可。上一轮结束后空闲超过 30 分钟再提交消息时，默认显示：

> CacheGate：已超过 30 分钟，本次继续发送。切换模式等功能见 cachegate help。

切换为拦截模式后，提示直接给出放行命令：

> CacheGate：已超过 30 分钟，本次已拦截。提交 cachegate allow 后，再发送消息即可放行一次。

## 使用与模式

以下命令均在 **Codex 输入框**单独提交，由插件在本地处理。

| 命令 | 作用 |
| --- | --- |
| `cachegate help` | 查看介绍和完整帮助 |
| `cachegate remind` | 仅提醒，随后继续发送（默认） |
| `cachegate confirm` | 超过 30 分钟时拦截，等待你决定 |
| `cachegate status` | 查看当前模式 |
| `cachegate allow` | 允许本会话下一条普通消息一次，可修改内容或切换模型 |
| `cachegate cancel` | 撤销本会话的单次许可和待确认记录 |

模式在使用同一状态目录的本机会话间共享，下次提交生效，更新插件后保留。

在拦截模式下，若要继续，先提交 `cachegate allow`，再发送想要提交的消息；许可不会自动发送消息。不想发送时直接不发送即可；已授予的许可可用 `cachegate cancel` 撤销。也可以切回仅提醒，或手动 `/clear` 新建会话。插件不会自动执行 `/clear`。

连续拦截多条消息后，`allow` 仍只放行本会话下一条普通消息一次。可以重发较早的消息、修改内容或切换模型；之前被拦截的消息不会排队自动发送。控制命令不消耗许可，重复 `allow` 不会叠加次数；没有待确认记录时不能提前授权。获准提交后消耗许可，执行结束或中断后重新开始空闲计时。

命令区分大小写，只识别独立的 `cachegate` 或 `cachegate <单个命令>`；普通说明、多行请求和代码块中的提及按普通消息处理。未知子命令会显示帮助入口。

## 更新与卸载

### 更新

在终端执行：

```bash
codex plugin marketplace upgrade cachegate
codex plugin add cachegate@cachegate
```

第一条刷新 GitHub 市场快照，第二条安装更新后的插件。更新后新建会话，并按 Codex 提示重新审阅 hook。模式和单次许可保留。从 0.2.5 或更早版本升级时，旧记录没有执行结束时间，会从下一轮实际结束或中断时建立新的计时基准。

### 卸载

在终端执行：

```bash
codex plugin remove cachegate@cachegate
```

卸载后保留本地状态。若同时需要停止跟踪该市场，再执行 `codex plugin marketplace remove cachegate`。

从旧的个人市场安装迁移时，先使用原市场名卸载旧插件，再按[快速开始](#快速开始)安装，避免加载两份 hook。

## 行为与数据

- **检查范围**：同一会话的用户消息，距上一轮执行结束或中断严格超过 1,800 秒时触发；首次见到的会话直接放行。任务内部的模型续发、工具循环和重试不在检查范围内。
- **计时规则**：任务运行期间不计为空闲，执行中追加消息不会因任务耗时较长而触发。被拦截或执行控制命令不会刷新计时；恢复会话时沿用已记录的结束时间。系统时钟回退时也按所选模式提醒或拦截。
- **缺失结束记录**：首次使用、从旧版升级，或进程异常退出、结束 hook 未运行时，无法判断空闲时长，因此不按超时提醒或拦截；下一轮正常结束或中断后恢复计时。不读取聊天记录补算结束时间。
- **单次许可**：仅限授予许可的会话，下一条普通消息获准提交后消耗；修改内容或切换模型不影响许可。其他会话不能使用此许可，`cancel` 可撤销许可和待确认记录。
- **本地数据**：保存模式、会话与 turn ID、时间戳及待确认、许可状态，不保存消息原文，也不读取聊天记录。不再生成消息摘要，旧版摘要字段仅为数据库兼容保留。

默认状态文件为 `${CODEX_HOME:-~/.codex}/cachegate/state.sqlite3`，可通过 `CACHEGATE_DATA_DIR` 指定状态目录。状态保存在插件安装目录之外。

**30 分钟是提醒阈值，不能证明缓存是否命中。** `/clear` 会开始新的会话上下文，不能恢复或延长过期缓存。参见 [Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching) 和 [Codex /clear](https://developers.openai.com/codex/cli/slash-commands#clear-the-terminal-and-start-a-new-chat-with-clear)。

根据 [Codex hooks 的运行约定](https://developers.openai.com/codex/hooks)，hook 未信任、被禁用、无法启动或执行超时时，宿主可能跳过检查。计时依据宿主发出的结束事件，无法观测服务端实际缓存状态。提交检查出错时会拦截；结束时间写入失败时只显示提示，不阻止停止或触发模型续写。
